2. 実装済（主な縦断）
--------------------
- 事務所/弁護士/相手先登録 → 案件（当事者・代理人・受任確認・member/barrier）→ 受任通知（T01）の自動差込 → 本文 AST 編集 → DOCX 生成（docxtemplater）→ PDF（LibreOffice headless、静的 Noto フォント埋込）→ 形式検査 → レビュー依頼 → 別弁護士の承認（hash 再検証）→ 正式 DOCX/PDF 取得 → 送付記録（他担当確認）。
- 独自 DOCX の登録 → Python 構造検査（run 分割タグ検出、対応外要素の位置付き拒否、残存個人情報候補）→ タグ対応付け/スキーマ保存 → 架空データ試作 → 3 点確認付き公開（sample_only / 所内承認版）→ 既公開版 immutable。
- 20 書式（templates/demo）: すべて sample_only、provenance に supervised=false。技術検証（検査・DOCX/PDF・フォント埋込・文字往復）は自動テスト済み。内容承認は未実施。
- 一括生成（20×50、100 上限、宛先別 snapshot、部分失敗の再試行、cancel）、証拠台帳（canonical 番号・一意・訂正別版）、提出パック（検査→ZIP: 連番名・manifest.json・確認一覧.txt・派生提出用 PDF）、送付/提出記録、更新候補（refresh-candidates）、外部編集版の再取込、CSV 取込/エクスポート、全量バックアップ export、pg_dump バックアップ/復元スクリプト、監査 append-only、PWA（manifest + 手書き sw.js）。
- セキュリティ: opaque cookie + CSRF/Origin + TOTP MFA（BFF 管理、replay 防止）、RLS（本人 claims）+ GRANT + cross-org トリガ + immutable トリガ、404 による存在秘匿、magic bytes/MIME/ZIP bomb/マクロ/OLE/外部参照/PDF JS 検査、ファイル quarantine と fail closed、job dedupe/lease/retry、ログ redact。

9. 既知の設計判断・制約
---------------------
- RLS は API より緩い箇所がある（admin が matter_members/matter_barriers を書ける、template_versions_write が org メンバー全員、matters_insert が staff を含む）。API 側で担当 lawyer/MFA/役割を強制しており、DB 直接アクセスは service role/運用者に限る前提。強化は追加 migration で可能。
- CSV 取込は先頭が = + - @ TAB CR の値を行ごと拒否する（保守的）。原文完全保存は JSON/TXT で提供。
- upload 進行状態と import preview はメモリ保持（単一 API プロセス前提、60 秒/10 分で失効）。複数プロセスでは sticky session か共有ストアが必要。
- pdfjs-dist 5.7 は Map.prototype.getOrInsertComputed を使うため apps/web/src/lib/polyfills.ts で補っている（Chromium 141 で確認）。
- LibreOffice 24.2 は可変フォントを Type3 で書き出すため静的インスタンスを生成（assets/fonts/static、git 管理外、Docker build で生成）。
- 可変フォントの静的化・docxtemplater inspect-module 用 lodash など、SOURCE_NOTES.txt に理由を記載。
- 和暦出力は全角数字（令和８年１０月６日）。ASCII 数字が必要な場合は formatWareki の digits オプション。
- 「同じ宛先が重複した一括生成」は 422。
- 名称 RayLaw の商標・重複確認は未実施。
